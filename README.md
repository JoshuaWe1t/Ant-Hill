# 1. Архитектурная декомпозиция (Godot / GDScript)

Проект оптимально организовать по компонентной схеме с разделением логики данных, мира и UI:

```
res://
├── assets/ (sprites, fonts, audio)
├── scenes/
│   ├── core/ (GameWorld.tscn, CameraController.tscn)
│   ├── entities/ (Queen.tscn, AntBase.tscn, Cocoon.tscn)
│   ├── buildings/ (BuildingBase.tscn, Shelter.tscn, Kindergarten.tscn, AphidFarm.tscn, Stockpile.tscn)
│   └── ui/ (HUD.tscn, BuildMenu.tscn, CommandMenu.tscn, GameOverScreen.tscn)
└── scripts/
    ├── autoload/ (GameManager.gd, ResourceManager.gd, EventBus.gd)
    ├── entities/ (AntAI.gd, Worker.gd, Soldier.gd, Babysitter.gd)
    └── world/ (ChunkManager.gd, GridManager.gd)
```

# 2. Ключевые Autoload (Singletons)

- `ResourceManager.gd`: Словарь текущих ресурсов (вода, протеин, фитомасса, дерево, глина, смола, шелк). Методы has_resources(dict) -> bool, spend_resources(dict), add_resources(dict). Эмитит сигнал resources_changed(new_balances).
- `GameManager.gd`: Глобальный стейт-машина (PREGAME, RUNNING, PAUSED, VICTORY, DEFEAT). Хранит таймер миссии, активные квесты и списки зарегистрированных муравьев/зданий. Проверяет условия победы и поражения.
- `EventBus.gd`: Централизованная шина сигналов для развязки систем (ant_spawned, building_placed, command_issued, chunk_unlocked).

# 6-дневный спринт разработки (Game Jam Roadmap)

Учитывая дедлайн в 6 дней, фокус смещен на раннее замыкание Core Loop на «серых коробках» с последующим накатом арта и балансировкой.

**Цель**: Передвижение камеры, координатная сетка, хранилище ресурсов.

**Задачи**:

- [READY] Реализовать CameraController2D (WASD + смещение к краям экрана, зум по колесику).
- [READY] Развернуть систему сетки/чанков (ChunkManager): разделение на Outer World и Ground.

- [READY] Настроить базовую сцену HUD с выводом значений ресурсов через сигналы.

## День 2: Сущности и базовый FSM юнитов

**Цель**: Королева, жизненный цикл куколок и спавн юнитов.

**Задачи**:

- [READY] Реализовать сцену Queen с параметром здоровья и кликабельной областью (CollisionObject2D + _input_event).
- [READY] Реализовать Cocoon: таймер созревания, перерождение в соответствующий класс муравья.
- [READY] Создать базу AntBase (FSM: IDLE, MOVE_TO, WORK, REST, DIE).
- [READY] Внедрить таймер жизни муравья (ant_worker: 120 с, soldier: 240 с, babysitter: 320 с) и периодическое потребление ресурсов.

## День 3: Система строительства и механики комнат

**Цель**: Размещение зданий, проверка ресурсов и коллизий.

**Задачи**:

- [READY] Сцена BuildingBase с логикой постройки (требование 2 рабочих, шкала прогресса).

## День 4: Система команд и Экспедиции

**Цель**: Взаимодействие с внешним миром и расширение базы.

**Задачи**:

- UI селектора команд при клике на Королеву (Разведка, Сбор ресурсов).
- Механика «Разведки»: выбор муравьев -> отправка к закрытому подземному чанку -> разблокировка чанка для строительства.
- Механика «Сбора ресурсов»: отправка группы во внешний сектор -> возвращение с ресурсами в Stockpile.
- Расчет бонусов и штрафов по матрице GDD (влияние классов юнитов на скорость и успех).

## День 5: Условия победы/поражения, UI/UX и Арт

**Цель**: Полноценная игровая петля от старта до финала.

**Задачи**:

- Реализовать глобальный таймер сессии и отслеживание целей победы (сбор N ресурсов / население N муравьев).
- Реализовать проверки поражения: смерть Королевы, нулевой баланс рабочих + отсутствие куколок, таймер = 0.
- Экраны Pause, Victory, Defeat с перезапуском сцены (get_tree().reload_current_scene()).
- Интеграция спрайтов из Aseprite: замена плейсхолдеров, добавление анимаций ходьбы муравьев.

## День 6: Балансировка, Полировка и Web-билд

**Цель**: Стабильный играбельный билд под Web и PC.

**Задачи**:

- Тюнинг параметров матрицы (потребление ресурсов, время стройки, таймер миссии на 7–10 минут).
- Добавление SFX (звуки кликов, подтверждения команд, сигналы тревоги).
- Экспорт в HTML5/Web: тестирование многопоточности, WebGL-шейдеров и звукового контекста.
- Сборка PC-версии и оформление страницы на itch.io.
